# Security audit — September 6, 2026

Scope: the repository at `6ba134c` and the v1.1.0 maintenance changes; served routes,
provider/search HTTP boundaries, SQL persistence, browser storage, build output,
dependencies, Git history, GitHub automation and Vercel configuration. This is a source,
configuration and non-destructive behavior review, not an independent penetration test
or a guarantee that no vulnerability exists. No production evidence was created,
modified or deleted during the review.

## Findings and remedies

1. **Excess database privilege on the serving path — fixed.** The previous credential
   could create databases and roles. Vercel production/preview now use a separate login
   with SELECT on the four performance tables, no table writes and no schema creation.
   Serving sessions additionally request read-only transactions, a 15-second statement
   timeout and a 10-second idle transaction timeout. A disposable PostgreSQL test proves
   that writes fail with SQLSTATE `25006` even when a writable credential is supplied.
   The collector retains its separate credential because it owns schema and evidence writes.
2. **Collector-only credentials in Vercel — fixed.** Removed `KMA_APIHUB_KEY` and
   `KMA_OBSERVATION_API_KEY` from website environments. Scheduled jobs retain them.
   Remaining secrets stay Sensitive in Vercel. New deployments receive the new values;
   historical deployments retain their earlier environment. Deployment protection is
   configured for all except custom domains.
3. **Incomplete merge gates for automatic maintenance — fixed.** Main now requires
   `verify`, `store-contract` and `Dependency review`, with an up-to-date branch.
   The patch/minor Dependabot workflow checks repository, author, head repository and
   base branch, requires a single signed Dependabot commit through the pinned metadata
   action, disables auto-merge when additional commits appear, and matches the expected head
   when enabling auto-merge. It never checks out or runs PR code. Major updates stay
   manual. The action allowlist permits only the reviewed metadata helper SHA.
   Scheduled collectors now have 20-minute job limits, and their checkout
   credentials are not persisted. Private vulnerability reporting is enabled.
4. **No custom edge-volume rule — observation phase.** Published a Vercel rule that
   logs `/api/` traffic above 150 requests per IP per 60 seconds. It does not yet block.
   Existing application limits still enforce 30 forecast and 20 search requests per
   minute per process/IP. Review traffic and test enforcement in preview before changing
   production behavior. Follow-up: [#140](https://github.com/mhju0/raintoday/issues/140).
5. **Recovery not rehearsed in this review cycle — verified.** A private custom-format
   PostgreSQL 18 backup restored into an isolated local database. UTC-normalized checksums
   and counts matched for all four tables: 97 stations, 3,077 captures, 1,746 observations,
   8,822 seed comparisons. TLS certificate verification was enabled for the backup.
   The backup and credentials are outside Git. See [OPERATIONS](../OPERATIONS.md).

6. **CLI deployment included Git-ignored retired media — fixed.** The first preview
   upload included the local cinematic archive. Added `.vercelignore` with the repository
   exclusions, including private environments, local agent state, scratch files and
   retired media. That preview was removed and replaced before release.

## Boundaries reviewed

The forecast accepts JSON only and bounds both declared and streamed input to 4 KiB.
Coordinates, elevation and names are validated before provider work. Search input is
bounded and encoded. Upstream hosts are fixed; users cannot submit a fetch URL. Provider
responses have byte limits and timeouts. Public failure responses do not return raw
provider errors or credentials. SQL uses bound parameters; the adapter's `unsafe` call
executes generated SQL with bound user values. There is no request-controlled shell,
file access, uploaded content or raw HTML rendering.

GPS requires an explicit interaction. Its record URL uses a public station identifier;
coordinates are not written to evidence tables. Browser storage retains a reduced-precision
last selection. React escapes text; CSP, frame restrictions, same-origin policies and
production HSTS provide additional browser protections. There are no user accounts,
authenticated mutation routes or Server Actions in this application.

## Limits and continuing duties

- Process-local limits and caches are not a global quota guarantee. Concurrent unique
  locations, multiple regions and distributed clients can still consume provider quota.
  The record page relies on bounded station-history caching and platform protections.
- CSP permits inline scripts/styles for the current Next.js rendering. This weakens its
  protection against a future HTML-injection defect; nonce-based rendering remains a
  possible separately tested change. No such injection path was found here.
- Most fixed-host provider requests retain fetch's default redirect behavior. No
  attacker-controlled redirect source was found; upstream compromise remains outside
  this review's assurances. Pirate Weather already rejects redirects.
- Old deployments retain old environment values. After a credential change, redeploy an
  older Git revision with current values when practical rather than reviving stale secrets.
- Neon account inspection confirmed six-hour history retention. Monthly manual backups
  leave a longer potential loss window; shorten the backup interval when needed.
- Provider account expiry dates and notification delivery need account confirmation.
  The logged-out data.go.kr session did not expose expiry dates.
  A September 7 reminder asks the owner to obtain the actual dates; it is not an expiry
  reminder. Ongoing observations are tracked in [#140](https://github.com/mhju0/raintoday/issues/140).
