# Probability bar baseline audit

Date: 2026-10-11 · antislop during mode, selected by the owner · report only

**Confirmed:** captions of different lengths can move individual probability bars and their 40% threshold segments vertically. This was reproduced on the live production page, not just inferred from source. No application code was changed during the initial report-only audit.

Follow-up: the owner subsequently authorized the fix and a service-wide responsive layout scan. Shared chart rows now separate plot geometry from caption height. The follow-up also addresses narrow-screen and enlarged-text wrapping in forecast summaries, provider/evidence rows, search controls, metadata and fallback pages. Release verification is recorded in the project handoff.

## 1. Different caption heights move the chart baseline

Priority: HIGH · antislop R-03 and C-4 (layout resilience)

The chart answers when rain is likely. Every probability bar needs the same zero line and the same 0–100% plotting height. A caption must not change either one.

On the live Seoul forecast, seven short captions read `기준 아래입니다.` while the 59% block read `비가 예상되는 구간의 시작입니다.`. The longer caption wrapped and its bar started 5.609px higher than the other bars at 1024, 1180, 1318 and 1440px. Its dashed 40% segment moved upward by the same amount. At 901px the baseline difference was 11.219px.

The bar heights themselves still reflected the percentages. The defect is the different origins: this makes comparison harder and creates a discontinuous threshold line. A higher percentage does not directly cause the shift; it often selects longer onset/peak/wet wording, which causes wrapping. An unpublished-value caption can cause it too.

Device model, browser, orientation, page version and effective CSS viewport of that observation are unknown. A tablet in landscape uses the affected layout.

## Why it happens

[`app/globals.css`](../../../app/globals.css#L1306) makes each column its own grid with `grid-template-rows: auto var(--local-track) auto`. The outer grid stretches columns to a common total height, but the inner grids calculate their rows independently. Free height is distributed among each column's auto rows. A taller caption consumes more height, changing the header row height and therefore the track's vertical position.

The optional rainfall lane adds a fourth, implicit auto row. The fixed probability track height alone cannot align the tracks because their starting positions still vary. The percentage and hint are nested in another grid; a short hint can also stretch within its allocated space, so its measured height is not always its natural line height.

Caption variants come from [`blockHint`](../../../components/local/LocalForecastExperience.tsx#L849). The threshold is positioned inside each track, so it inherits the same displacement. The date tag is absolutely positioned and was not the cause in these checks.

## Suggested fix

**Use shared chart rows across all eight columns.** Define a common header row, fixed probability plotting row, content-sized percentage/caption row, and optional rainfall row on the parent. Have the columns participate in those shared rows, preferably through CSS row subgrid, subject to the project's supported-browser policy.

This lets the longest caption determine one shared caption-row height. All probability tracks then keep the same top and bottom, including when a caption wraps, text grows, a value is unpublished, or the rainfall lane is absent. Preserve the existing mobile sideways scroll, hidden captions below 900px, proportional 0–100% heights, zero ticks, missing-value hatching, date tags, keyboard scrub and separate mm scale.

Avoid caption-specific offsets or a fixed caption height. Those depend on today's wording and font size and can break with larger text or longer missing-data captions. Shortening captions may improve reading, but it does not establish the baseline invariant.

For a future implementation, verify track tops, bar bottoms and threshold positions differ by no more than 1 CSS pixel across columns. Include equal probabilities with different caption roles so the test can expose alignment independently of bar height.

## Verification and limits

- Live production page: Chromium, real Seoul response, 11 viewport widths from 320 to 1440px.
- Controlled response: real deployed UI with a clearly synthetic eight-block forecast, exercised in Chromium and WebKit. It includes dry, onset, peak, wet, zero and unpublished probabilities, a day boundary, and mixed published/missing amounts. [Fixture](evidence-006-2026-10-11/synthetic-forecast.json), [measurements](evidence-006-2026-10-11/synthetic-measurements.json), [WebKit desktop screenshot](evidence-006-2026-10-11/synthetic-webkit-1440.png).
- Both engines reproduced 5.609px displacement at 1024/1318/1440px with the mm lane, about 8.4px without it, and up to about 16.8px at 901px without it. Narrow-width differences were at most 0.11px, below a meaningful visual defect.
- A browser-only 200% root-font simulation on the live page increased the displacement to 22.438px at 1024/1440px. At 390/768px it remained zero. This is a text-size stress check, not a physical-device accessibility-setting test.
- No whole-page horizontal overflow appeared in the measured states. The phone ribbon's own horizontal scrolling is intentional. No runtime page errors occurred in either controlled browser run.
- Physical iPhone/iPad Safari, Android browsers, native text enlargement and the original phone state were not tested. WebKit is an engine check, not a device-Safari certification.
- The proposed fix has not been implemented or tested. No build, release, deployment or production data write was performed.

Scoped antislop gate: baseline resilience **FAIL**, documented as finding 1; viewport overflow **PASS** (DOM measurements); evidence integrity **PASS** (live and synthetic results distinguished); owner scope **PASS** (report and screenshots only). The finding remains open under the owner's explicit instruction not to fix anything. Other whole-app gate items are outside this focused audit.
