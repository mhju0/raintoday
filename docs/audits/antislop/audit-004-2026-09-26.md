Date: 2026-09-26
Mode: fix as found. The owner asked for the same issue classes as audit 003 to be fixed at every size. The antislop skill was not loaded in this session.
Scope: `fix/desktop-tablet-audit` on top of `cc51c1e` (#179), as a production build.

## Owner's rules (added to audit 003's)

- Every rule keeps the same gap to its text: the 오늘비 header rule matches the facts list's rules, about 16px each side.
- A paragraph of two or more lines never ends on a stub. The last line fills at least half the widest line, or the text is set so that it does.
- Nothing is cut off at any size, including a browser dragged narrower or wider.

## Method

- Engines: Playwright WebKit and Chromium, with the page's own web fonts.
- Named sizes (43), CSS px:
  - iPhone: 320–440 (from audit 003)
  - iPad portrait: 744, 810, 820, 834, 1024, 1032
  - iPad landscape: 1133, 1180, 1194, 1366, 1376
  - iPad Split View: 507, 551, 678
  - MacBook full-screen browser: 1280, 1440, 1470, 1512, 1710, 1728, plus a 1920 display
  - Mac split screen, 1/3: 490, 504, 576
  - Mac split screen, 1/2: 735, 756, 855, 864
  - Mac split screen, 2/3: 980, 1008, 1152
  - Mac split screen, 3/4: 1102, 1134, 1296
- Live resize: one loaded page per view, resized in place from 1920 down to 320 in 8px steps, with no reload.
- Views: the chooser and the loading overlay, the forecast in both densities for two live locations, and `/behind-the-data`.
- Checks: audit 003's four, plus two more:
  - **Short last line:** the last line of any multi-line block under 50% of its widest line.
  - **Line-start punctuation:** a line that opens with a separator or closing mark.

## Findings and fixes

1. **The header rule sat 27px under the wordmark and 52px (77px on desktop) above the chooser.** The facts list keeps about 15px.
   - The header is now 3.45rem, which is the 44px touch target plus about 16px each side of the text.
   - The chooser's top padding is 0.65rem.
   - The eyebrow no longer picks up the intro paragraph's 1rem top margin: `.local-chooser-copy > p` matched it too.
   - Measured after the fix: 18px above the rule and 15px below, at 390 and at 1440.
2. **Short last lines, 17,354 before the fix.** Every page root now sets `text-wrap-style: balance`.
   - It is the longhand on purpose: the `text-wrap` shorthand also resets the wrap mode, which undid `nowrap` on `.local-keep` and made Safari split the terms it protects.
   - The chooser intro's own `text-wrap: pretty` was removed so it inherits balance.
   - One `/behind-the-data` note was longer than the six lines Chrome will balance, so it is now two paragraphs.
3. **Split words at 352–632:** "0% / 는", "% / 에서", "% / 로" and "날· / 안".
   - Each is now bound with `.local-keep`: 0%는, {floor}%에서, {floor}–{cap}%로, 비 온 날·안 온 날.
4. **A colon or comma at a line end, which balancing surfaced at 320–328.**
   - The 채점 사이클 kicker drops its comma and binds "06:10 · 18:10 KST".
   - The folded stub rows ("서비스 5곳 비교: …") stack title over value with no colon whenever the row is under 24rem. This is a container query, so it follows the row, not the viewport.
5. **A separator dot opening a line**, for example "…Pirate Weather / · WeatherAPI".
   - A no-break space now ties each dot to the name before it in:
     - the provider lists (chooser and loading)
     - the footer
     - the benchmark line
     - the seed table header
     - the `/behind-the-data` station line and source list
